# Дорожная карта VARKENZA ROLEPLAY

> Документ отражает **технические этапы**, а не обещание сроков. Текущий этап — **альфа**. Процент готовности пока не используется: веб-прототип и игровой мод развиваются на разных технологических основах.

[Вернуться на главную](../README.md) · [Запуск и настройка](SETUP.md) · [Открытые задачи](https://github.com/Zeihos/VARKENZA-RolePlay/issues)

## Уже организовано

- [x] Публичный GitHub с отдельными каталогами исходников, ассетов и инструментов.
- [x] Оригинальный `open.RP` подключён как Git-подмодуль на зафиксированной ревизии с сохранением лицензии.
- [x] Существует локальный прототип сайта на Node.js/SQLite с кабинетом, форумными и административными разделами.
- [x] Созданы отдельные прототипы Windows-консоли, монитора и лаунчера.
- [x] Автоматические проверки исходников и подготовки базового мода запускаются в GitHub Actions.

## Этап 1. Игровое ядро

- [ ] Завершить компиляцию Pawn-мода на выбранной версии зависимостей без критических ошибок.
- [ ] Подтвердить запуск серверной части и загрузку игрового мира.
- [ ] Настроить MySQL, миграции и резервные копии для игровых данных.
- [ ] Проверить вход/выход игроков, сохранение аккаунта и работу базовых команд.
- [ ] Проверить совместимость с целевой версией open.mp отдельно от SA-MP 0.3.DL.

**Текущая задача:** [#3 — компиляция и запуск](https://github.com/Zeihos/VARKENZA-RolePlay/issues/3). Активные изменения в [PR #5](https://github.com/Zeihos/VARKENZA-RolePlay/pull/5) нельзя считать релизом до прохождения сборки.

## Этап 2. Единая платформа

- [ ] Определить одну серверную модель аккаунтов и персонажей.
- [ ] Спроектировать соединение Node.js-сайта с MySQL-модом.
- [ ] Проверить согласованность баланса, гаража, статусов и прав доступа.
- [ ] Реализовать безопасную миграцию существующих тестовых данных, если понадобится.
- [ ] Добавить интеграционные тесты сквозных сценариев «сайт → игра → сайт».

**Текущая задача:** [#4 — архитектура и интеграция](https://github.com/Zeihos/VARKENZA-RolePlay/issues/4).

## Этап 3. RP-механики

- [ ] Довести до устойчивого состояния авторизацию и создание персонажа.
- [ ] Проверить игровые работы, экономику, банк, недвижимость и транспорт.
- [ ] Развивать фракции, организации, инвентарь и взаимодействия.
- [ ] Создать надёжную модерацию, логи и античит.
- [ ] Провести игровые тесты, измерить производительность и устранить ошибки.

## Этап 4. Публичные сервисы

- [ ] Завершить сайт и личный кабинет для реальных пользователей.
- [ ] Доработать форум и связать права со сквозной системой аккаунтов.
- [ ] Подготовить Windows-программы и механизм обновлений.
- [ ] Настроить защищённый хостинг, HTTPS, мониторинг и резервное копирование.
- [ ] Провести закрытое тестирование, затем рассматривать публичный релиз.

## Когда проект можно считать готовым?

Только после успешной компиляции, запуска и проверки с реальными игроками, корректного сохранения данных, устранения критических багов и базового аудита безопасности. **Зелёные CI-проверки исходников сами по себе не означают готовность игры.**
